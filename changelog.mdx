## 11 November 2026 · Compatible dataset and discovery API

- REST dataset aliases `sportsbooks`, `kambi` and `pilot` preserve the existing namespaces and access scopes.
- Fixture/odds reads accept opt-in `view=standard`, retaining exact IDs and the complete original record. Default legacy responses remain available.
- Added `GET /v1/participants` and `GET /v1/fixtures/{fixture_id}`, using existing reader, account and source controls. Player identities remain explicitly scoped or missing.
- The playground adds dataset labels, response-view selection and the new reads. No source collection or customer grants are enabled by these changes.

## 11 November 2026 · API reference and playground refresh

- Core sports endpoints now lead the API navigation. Advanced capabilities and workspace/operator contracts have separate sections; existing reference URLs remain available.
- Native fixture, odds and player-prop routes are included, with retained/live scope and exact capture identity documented separately from canonical odds.
- The signed-in playground groups requests, shows endpoint-specific filters and links directly to each reference. Native empty-page credits are documented separately from canonical data.
- Reference pages render parameters once. Hosted read examples include required namespace and fixture/capture filters, use header credentials and disable redirects where supported.

## 11 November 2026 · Hosted docs and account access

- Documentation is live at `https://docs.oddswire.io` on Mintlify, with search, Markdown exports, machine-readable contracts and its own sitemap.
- Existing `https://oddswire.io/docs/...` links permanently redirect to the matching hosted docs pages. The data MCP guide is `/mcp-client`; `/mcp` is reserved by Mintlify.
- Production email/password login and email verification are configured at `https://oddswire.io/app`. Verified signup creates an empty personal workspace automatically.
- The HTTPS API is deployed at `https://api.oddswire.io`. Real retained pre-match data reads have been verified under a separate founder-only internal review. This does not grant customer access.
- Public quick starts use cURL, Python standard-library HTTP and Node.js fetch. They do not require the private product checkout or unpublished packages.

## Current limits

New signups have no data grants or allocation. There is no public paid checkout, general source-data licence or registry release of the SDKs. Streaming, history/export, outbound alerts, Terminal and the data MCP client have separate restricted or preview boundaries. In-play has synthetic local validation only. See [Current availability](/availability).

## Contract version

The API uses `/v1`. Request/response schemas derive from the implemented gateway contract; hosted documentation supplies the HTTPS server address and current availability notes. Readers should tolerate added optional fields and new missing/error codes. No production uptime, latency or six-month deprecation SLA is promised by publishing this contract.
