Oddswire is a private sports-data pilot. The workspace and HTTPS API are deployed, but **creating an account does not unlock odds data or allocate credits**.

## What you can do now

1. [Create an account or sign in](https://oddswire.io/app). Complete the email verification shown by the sign-in flow. Your personal workspace is created automatically; there is no local installation or separate workspace-creation command.
2. Open [Coverage](https://oddswire.io/app/coverage) and [Usage](https://oddswire.io/app/usage). They show your account's actual permissions and allocation. An empty scope is expected for a new account.
3. If your account is approved for API access, an owner or admin can create a key in [API keys](https://oddswire.io/app/keys). A key authenticates you; it does not add permissions or credits.
4. Start with the free access check in the [cURL](/quickstart-curl), [Python](/quickstart-python) or [JavaScript / TypeScript](/quickstart-typescript) guide. Only request data after your returned entitlements include the required scope.

If you need access, [contact Oddswire](mailto:spazman2c@gmail.com) with your intended use and required coverage. Access is reviewed; there is no public self-serve paid plan or guaranteed approval. Do not email API keys or session tokens. A beta invitation is only relevant when one has actually been issued to your account.

## API address

Use `https://api.oddswire.io` as the base URL. Endpoint paths already include `/v1`, for example `https://api.oddswire.io/v1/account/entitlements`. Do not add a second `/v1`.

The examples on this site use standard HTTP tools. They require no private repository, SDK package, local server, Docker or `make` command. Use [the signed-in playground](https://oddswire.io/app/playground) if you prefer not to write code.

## Understand availability before integrating

Read [Current availability](/availability) for the difference between deployed account/REST access and features documented as restricted previews. A published endpoint schema is not a promise that your account can use it. New users do not inherit founder-only internal access.

Keep decimal values as strings, preserve native identifiers, inspect every `missing[]` entry, and respect quote freshness. See [Data and coverage](/data) and [Errors and credits](/errors).

## Contracts and documentation tools

Download [OpenAPI](/openapi.json), [AsyncAPI](/asyncapi.json) or the [WebSocket schema](/websocket.schema.json). OpenAPI uses the hosted HTTPS base URL; schemas describe implementation contracts and do not activate restricted features.

Each guide is available as Markdown. Coding assistants can read [/llms.txt](https://docs.oddswire.io/llms.txt) and [/llms-full.txt](https://docs.oddswire.io/llms-full.txt). These contain documentation, not API credentials or source prices.

## Your first signed-in request

Key creation currently requires approved API access; a new workspace cannot create a data key while beta access is disabled. Once your account is eligible, [create a key](https://oddswire.io/app/keys) and open the [private playground](https://oddswire.io/app/playground) in the same tab. It starts with the free entitlements check; your selected tab-memory key is filled into the private cURL/Python snippet. Public docs never receive your key. Copied snippets contain a credential: keep them private. This control response needs no credits and is an access check, not an odds-data request. Instant API access after signup is not currently available.
