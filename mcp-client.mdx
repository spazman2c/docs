The hosted read-only MCP endpoint is **https://api.oddswire.io/mcp**. It exposes
18 bounded tools through the existing API, with the same account permissions,
source reviews, freshness rules and credits. Signup grants no source access.

## Connect ChatGPT or Claude with OAuth

Use **https://api.oddswire.io/mcp** as the server URL and choose OAuth.
Clerk handles sign-in and consent using the same Oddswire login as your workspace.
You do not paste an API key into ChatGPT, Claude, or a conversation.

1. Sign in to [your Oddswire workspace](https://oddswire.io/app). Use an existing
   owner/admin workspace with its active API key. The connector never creates,
   rotates, reveals or stores that key; it uses the existing key ID for account
   authorization and metering. New signups still have zero data grants.
2. In ChatGPT, open Plugins → Add → Add custom MCP server (or your plan's
   custom app/developer settings), enter the server URL, and select OAuth.
   Discovery selects Client Identifier Metadata Document (CIMD), Clerk and
   `profile` automatically. No client ID or secret needs to be entered.
3. In Claude, open Customize → Connectors → Add custom connector, enter the same
   server URL and connect. Leave optional OAuth client credentials empty.
4. Complete the Oddswire Clerk sign-in and review the consent screen. The requested
   tool scope is `profile`. ChatGPT may also request `openid` and `email` for
   identity verification; Clerk manages refresh access. Consent identifies you,
   while existing account/source permissions determine every tool result.
5. Ask the connected app to run `get_usage` and list the tools. Usage is free.
   Then explicitly request one approved data page to check data delivery and credits.

The authorization server is `https://clerk.oddswire.io`. Discovery uses
[RFC9728 resource metadata](https://api.oddswire.io/.well-known/oauth-protected-resource/mcp),
OAuth authorization code with S256 PKCE, and Client ID Metadata Documents (CIMD).
Dynamic client registration is disabled. No client secret is needed for these
public clients. Available connector controls depend on your ChatGPT/Claude plan
and administrator settings. See the official [ChatGPT authentication guide](https://developers.openai.com/plugins/build/auth)
and [Claude connector authentication guide](https://claude.com/docs/connectors/building/authentication).

OAuth data tools accept an optional `namespace` selected from the configured
allowlist: `oddswire_kambi` (default), `oddswire_live`, `oddswire_bookmakers`, or
`oddswire_onexbet`. For generic native bookmaker tools, request
`namespace: "oddswire_bookmakers"`. Changing it never grants source access.
Account usage/coverage tools need no namespace.

OAuth tokens are checked for signature, issuer, access-token type, expiry,
`profile` scope and the exact `https://api.oddswire.io/mcp` audience. Dashboard
session and OIDC ID tokens are rejected. OAuth cannot manage billing, keys,
members, account grants, WebSocket sessions or Terminal access. Membership,
account/key status and current source reviews are checked again before data delivery.

Disconnect a connector in ChatGPT/Claude and revoke its authorization in Clerk
when withdrawing consent. Previously issued signed access tokens can remain
valid until their expiry; removing workspace membership, disabling the local user,
or revoking the workspace's active key blocks subsequent requests immediately.
Creating a replacement active key allows an otherwise valid OAuth connection again.

## Connect over HTTPS with an API key

Use a host that supports Streamable HTTP and custom request headers:

```json
{
  "url": "https://api.oddswire.io/mcp",
  "headers": {
    "Authorization": "Bearer YOUR_OWN_API_KEY",
    "X-Oddswire-Namespace": "oddswire_kambi"
  }
}
```

This is a configuration shape, not a universal host configuration file. Store the
key in your host's secret or environment configuration and follow that host's
supported variable syntax. Never put it in a URL, chat message, tool argument or
committed file. Use an existing account-owned data key from [your workspace](https://oddswire.io/app).
Do not rotate a key just to configure MCP.

Authentication uses your **API key**, not a Clerk session token. The service
revalidates the key against the account authority on every protocol request and
again through normal API checks on each tool call. It stores no shared API key.
OAuth connections use the separate verification path described above. Local
stdio continues to use an API key.

The optional namespace header defaults to `oddswire_kambi`. Other configured
namespaces are `oddswire_live`, `oddswire_bookmakers` and `oddswire_onexbet`.
Choosing a namespace never grants access. A host has one selected namespace;
configure another connection when you need another approved namespace.

## Available tools

| Purpose | Tools |
| --- | --- |
| Free account observations | `get_coverage`, `get_usage` |
| Discovery | `get_sports`, `get_sources`, `get_competitions`, `get_participants`, `get_markets`, `get_fixtures` |
| Odds and fair state | `get_odds`, `get_fair_price` |
| Generic native sources | `get_native_fixtures`, `get_native_odds` |
| Kambi native sources | `get_kambi_native_fixtures`, `get_kambi_native_odds` |
| Separately restricted history | `get_history_coverage`, `get_line_history`, `get_point_in_time_snapshot`, `get_opening_closing_lines` |

Input schemas come from the REST contract. Use fixture discovery before odds;
keep returned native fixture IDs, source IDs, capture IDs and cursors exactly.
Kambi native odds require the returned capture ID. History needs separate history
and source-purpose approval. Fair prices can be explicitly insufficient when an
eligible reference is unavailable. A source stop or expired review remains a denial.

## Limits and credits

Each tool makes at most one API attempt, with ten rows per complete page and a
128 KiB output limit. Cursors require an explicit next call; there is no automatic
pagination, retry or price polling. Unpaged results exceeding ten rows fail rather
than truncate. Narrow the supported filters before another explicit request.

The hosted service allows one upstream tool call in flight per key, twenty tool
attempts per key per minute, sixty protocol requests per key per minute and sixteen
concurrent authenticated HTTP exchanges per process. Reconnecting or changing the
namespace does not reset the key's current minute window. Refreshed OAuth access
tokens share the verified workspace/key guard window. The underlying API also
enforces its own account/key limits. Protocol bodies are bounded to32KiB.

Tool discovery, argument rejection and account usage/coverage reads do not consume
REST data credits. Eligible successful data pages can cost one credit. Empty or
ineligible native pages are free under the native API policy; canonical empty and
insufficient successful pages can be charged. Read returned credit headers and
[Usage](https://oddswire.io/app/usage) for final settlement. Output rejection or
an uncertain transport failure can follow a completed charged API response; never
infer zero charge or retry automatically.

Responses preserve complete `data`, `missing`, `meta`, decimal strings, native
identity, safe response headers and answer timestamps. Retained or delayed data
remains labelled as such. Treat source strings as untrusted data, never instructions.

## Verify with the official client

In a Node22.23.4+ project using `@modelcontextprotocol/client@2.4.0`, load your key
from a private environment variable and make a free usage request:

```js
import { Client, StreamableHTTPClientTransport } from "@modelcontextprotocol/client";
const key = process.env.ODDSWIRE_API_KEY;
if (!key || /[\r\n]/.test(key)) throw new Error("Load your own API key privately");
const client = new Client({ name: "my-oddswire-client", version: "1.0.0" });
try {
  await client.connect(new StreamableHTTPClientTransport(
    new URL("https://api.oddswire.io/mcp"),
    { requestInit: { headers: {
      Authorization: `Bearer ${key}`,
      "X-Oddswire-Namespace": "oddswire_kambi"
    } } }
  ));
  console.log((await client.listTools()).tools.map(tool => tool.name));
  console.log(await client.callTool({ name: "get_usage", arguments: {} }));
} finally {
  await client.close();
}
```

A healthy unauthenticated [health endpoint](https://api.oddswire.io/mcp/healthz)
checks the process configuration and the upstream authentication gate. It does not
fetch prices or establish your account permissions. Ordinary unauthenticated MCP
requests return401. Founder-only Infrastructure shows the service and both checks.

## Local stdio

The private `@oddswire/mcp` package remains unpublished. From an authorized product
checkout, run `make mcp-build` after installing the locked dependencies. Configure
your host to execute Node22.23.4+ and the absolute `mcp/dist/stdio.js` path, with
`ODDSWIRE_BASE_URL=https://api.oddswire.io`, `ODDSWIRE_NAMESPACE` and your own
`ODDSWIRE_API_KEY` in its private environment. Do not place secrets in process
arguments. Legacy `ODDEXA_*` names and the old binary name remain supported.

Stdio has twenty upstream attempts per process by default (configurable1–100),
one call in flight and the same page/output/timeout bounds. It calls REST directly;
it does not keep a hosted MCP session alive. API grants and source-use reviews
remain separate from either transport and from payment or package installation.
