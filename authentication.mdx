## Sign in to the workspace

Open [oddswire.io/app](https://oddswire.io/app), follow the email/password sign-in flow and complete the displayed email verification. Use the sign-in options offered on that page. Verified signup creates your personal workspace automatically.

New accounts start with **no API or Terminal data access and no credit allocation**. Signup, email verification and key creation do not activate source-data access. Review [Current availability](/availability), [Coverage](https://oddswire.io/app/coverage) and [Usage](https://oddswire.io/app/usage).

## Authenticate HTTP requests

An owner or admin can create, rotate or revoke account-owned keys in [API keys](https://oddswire.io/app/keys). The account has a one-active-key cap. A new raw key is shown once; store it privately. Rotation replaces the old key. Revoked keys must not be reused.

Send exactly one `X-API-Key` header to `https://api.oddswire.io`. Enter your key only in the API reference’s authorization field or your own private application configuration. Never put credentials in URLs, published code, chat or email. Do not send both a data key and a session token. A data key cannot manage account membership, create other keys or operate billing.

Start with `GET /v1/account/entitlements`. It is free, even without data credits, and tells you the account's current `namespaces` and `features`. An empty scope is a valid access result, not an instruction to try a different namespace. Data requests require the corresponding scope and allocation.

## Try a request in the reference

Open [Check API access](/reference/getEntitlements), select **Try it**, enter your `X-API-Key` and send the request. Use a namespace returned by that response for fixture and odds requests. The tester sends real requests through Mintlify’s request proxy to `https://api.oddswire.io`. It does not sign in to your workspace or activate access.

The browser may remember the key between pages and visits. Use a private device and clear the saved authorization when finished. Data requests follow the usual credit rules; the access check is free. Requests run when you send them.

Manage account settings, members, keys and billing in [your workspace](https://oddswire.io/app). You do not need a workspace session token to use the data API reference. API and Terminal remain separate product scopes.

## Access problems

A 401 means the header credential is missing, invalid, expired or revoked. A 403 means the authenticated request is not permitted. A 402 can mean no data allocation or exhausted included credits. Use [Errors and credits](/errors) and contact support with the request ID; never send the credential itself.
