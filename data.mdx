Every data request names a namespace. Canonical bulk odds also requires a `fixture` or `competition` filter. Discover fixtures and sources inside that namespace; never join separate stores by coincident numeric IDs. `books` contains **source/region IDs**, not brand slugs. Correlated brands in the same feed family do not become independent sharp references.

## Choose canonical or native data

The [endpoint guide](/endpoints) separates canonical `/v1/fixtures` and `/v1/odds` from the source-native route families. Native reads use `native_fixture`, not a canonical `fixture` ID. Kambi native odds also require the original `capture_id` returned by discovery; `mode=retained` preserves historical times and `mode=live` additionally checks the approved live scope and current controls.

Native values retain `native_unit` or the original record's unit. Read player, fee and settlement verification fields explicitly; a native prop candidate is not a reviewed cross-source player market. `props_only=true` filters available native evidence, not a complete player-prop catalogue.

## Quote identity and units

Preserve `quote_key`, native fixture/offer/outcome IDs, source/region, side and depth. More than one native offer may exist on the same canonical line. Reviewed grouping/orientation is explicit; source-local identity is not a reviewed match. Market family, period, quarter line and settlement terms must be compatible before comparison.

`decimal_odds`, native probabilities and sizes are decimal **strings**. A probability is not decimal odds. A team's NO contract is not the opposing 1X2 outcome. Fees, commissions, liquidity and settlement metadata remain source-specific. Unknown/nonzero exchange fees and push/split payouts are unsupported in the fair service.

## Freshness and missing coverage

`source_ts` is nullable. `seen_ts` is observation time. `confirmed_ts` records the last successful confirmation; unchanged successful observations refresh it without another price tick. `sent_ts` only records delivery and cannot refresh source freshness.

Read quote eligibility/state and age against `freshness_limit_seconds`; distinguish active, suspended, unavailable and stale states. Read **all** `missing[]` entries, including when `data` is nonempty. They identify uncollected, denied, stale, blocked, incompatible or insufficient coverage. A response is never proof that every planned bookmaker or market is covered.

The read-only API does not collect new prices. Free account coverage describes available scope and retained freshness; it is not an uptime guarantee. Fixture discovery may return no data. Bounded retained history requires separate history/export grants; opening/closing and as-of eligibility remain pre-match-only. Production coverage guarantees remain unverified.

## Fair price

`GET /v1/fair` requires fixture and settlement rule as well as namespace. Use discovered market metadata. The service reevaluates current reviewed inputs, eligibility, feed groups and configured weights. It exposes sources/method/filters and explicit insufficiency rather than serving an expired calculation.

There is currently **no configured eligible sharp reference**, so the pilot consensus is insufficient. Diagnostic vectors are not consensus prices. A 200 insufficient result still costs one credit. Technical source access does not confer customer display, derived-use or redistribution rights.

## In-play availability

Working collection remains pre-match-only. The implemented in-play lifecycle has only synthetic development validation and requires an explicit API `inplay` grant. Read
`inplay.mode` on source/coverage metadata and `fixture_phase` on quotes; a
`local_test_only` mode is not real provider coverage. See [in-play scope and
session recovery](/inplay) before requesting `status=live`.
