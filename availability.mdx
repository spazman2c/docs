## Deployed today

| Surface | What is working | What a new user receives |
| --- | --- | --- |
| Public docs and calculators | Hosted documentation and free browser tools | No account is needed for docs or [calculators](https://oddswire.io/tools) |
| Customer workspace | Production email/password login, email verification and automatic personal workspace setup | An account with no API/Terminal data grants or credit allocation |
| Account controls | Keys, usage, coverage and account permissions in the signed-in workspace | Controls appropriate to your role; they do not unlock a feed |
| HTTPS REST API | `https://api.oddswire.io/v1/...` authenticates requests and enforces permissions, freshness and quota | Data requires an explicitly approved scope and allocation |

Production Google/GitHub social sign-in is not configured. Use the email/password flow currently offered by Oddswire; logging in to another service with Google does not configure Oddswire social login.

The REST contract includes both canonical sports data and separately gated native fixture/odds routes. Native reads include source-labelled player-prop candidates; those labels do not establish canonical player identity or settlement compatibility. Kambi distinguishes original retained snapshots from separately approved live mode. Use the [endpoint guide](/endpoints) to choose the correct route family.

Internal source reviews are expiring and founder-only. **They are not customer availability, a data licence, or an entitlement included with signup.** Collection and source controls can change independently of these docs. Read actual account coverage and response freshness; no coverage or uptime guarantee is implied.

## Documented contracts that are not public launches

| Capability | Current boundary |
| --- | --- |
| WebSocket stream | Implemented protocol, independently gated `websocket` and odds grants; no new-user stream access or browser ticket bridge |
| History and exports | Implemented bounded contracts; separate history/export grants and source-purpose review required; not enabled for new accounts |
| Line-move webhooks | Implemented signing/retry contract; production outbound delivery and source-use approval are not configured for general customers |
| Fair-price consensus | No configured eligible sharp reference; an insufficient result is not a fair price |
| In-play | Synthetic local validation only; working collection remains pre-match-only |
| Terminal | Local implementation and separate Terminal permissions; no customer rollout |
| Python/TypeScript SDKs and data MCP client | Private preview artifacts; no npm/PyPI release, public installation or hosted data MCP endpoint |
| Billing and beta administration | Restricted test/operator contracts; no public paid checkout, automatic data grant or general beta enrollment |

Pinnacle's access stop remains in place. BetCity is blocked, and the 1xBet/MELBET work remains access-only rather than a working odds feed. Planned providers are not current customer coverage.

## Choose your next step

- New account: review [authentication](/authentication), then run a free [access check](/quickstart-curl).
- Approved REST integration: use namespaces and features returned by [Get entitlements](/reference/getEntitlements), then discover fixtures before requesting odds.
- No approved data scope: use the public calculators, inspect the contracts, or contact support. Repeating a denied request will not enable access.

These docs do not change source permissions, country/region restrictions, account expiry, or the applicable use review. Published schemas, successful technical collection and account signup are separate from permission to display or redistribute data.
