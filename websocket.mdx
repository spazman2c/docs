Streaming requires an active WebSockets add-on, `odds` and `websocket` permissions, and access to the selected sources. New accounts do not receive stream access automatically. Check [Coverage](https://oddswire.io/app/coverage) and [availability](/availability).

Use `wss://api.oddswire.io/v1/ws` for a header-authenticated server connection. For browser clients, use the short-lived ticket flow below. Stream messages do not consume REST data credits.

## Try the workspace WebSocket lab

Open [WebSocket lab](https://oddswire.io/app/websocket) when your account has access. Select the active key, available dataset/source, mode and fixture. Use only selections returned for your permitted scope.

Press **Connect** to start a fresh subscription. **Resume** uses the last fully accepted cursor where that delivery mode supports it. The connection status and confirmation ages tell you whether the displayed data is current. Use the table search to narrow visible rows; hiding a row does not change the underlying subscription.

The keep-connected option reconnects eligible sessions and requests a fresh snapshot when required. Access failures stop the connection. Retained native snapshots remain historical; they do not become live when the lab reconnects. Disconnect when you finish. Do not put an API key in a browser WebSocket URL.

## Authentication and subscription

The protocol requires one `X-API-Key` header and the `oddswire.v1` subprotocol. Use a server-side WebSocket library that can set headers, and WSS for a remotely supplied endpoint. Native browser WebSocket constructors cannot provide the required header, and `/v1/ws` rejects origin-bearing upgrades. The separate `/v1/ws/browser` endpoint uses verified-login, single-use first-frame tickets as described below. Never put a key or ticket in a URL or subprotocol.

After the server's `hello`, send a `subscribe` command with an `id` and string-valued `params`. Choose `namespace`, fixture/competition and source IDs from your actual approved discovery scope. Do not copy illustrative IDs as a working subscription. Namespace plus fixture(s) or competition(s) is required. There is one active subscription per connection, with no REST `limit` or `cursor` inside `params`. Resume uses the last fully applied opaque cursor at the command's top level.

## Apply state safely

1. Treat `delivery_seq` and namespace positions as exact decimal strings. Delivery sequence resets per connection.
2. A `snapshot`, `resumed` or `state` frame with `replace: true` replaces the entire view, including empty data. Retain `missing[]`.
3. Apply each delta's ordered changes atomically, keyed by native `quote_key`. Preserve event IDs and A → B → A changes; filtered positions may jump.
4. Save a cursor only after the full frame is applied. Resume is bounded to five minutes and retained journal capacity.
5. On `resnapshot_required`, clear the view and cursor and resubscribe without a cursor. A disconnect makes retained quotes unconfirmed. A heartbeat or `sent_ts` cannot refresh a source confirmation.
6. Keep a reader active for protocol ping/pong, including between price changes. Slow or stalled clients can be disconnected. Reconnect deliberately with a fully applied cursor or request a fresh snapshot.

Current grants, source-purpose rules, expiry and freshness remain enforced. Metadata, mapping, lineage, journal or access changes can require a new snapshot. Messages do not consume REST credits, but that does not grant stream access.

The implemented limits are 16 connections per service instance, two per account and one subscription per connection. Narrow subscriptions to your permitted scope. These limits do not constitute a capacity or latency commitment.

Download the [AsyncAPI contract](/asyncapi.json) and [wire schema](/websocket.schema.json). [Data and coverage](/data) explains source freshness and explicit missing data.

## Browser authentication

A verified owner/admin session can POST an existing account-owned `key_id` to the
same-origin workspace `/api/websocket/ticket`. This exchanges the current Clerk
session for a digest-only, single-use credential; it does not grant streaming or
source access. Connect to the returned WSS URL with `oddswire.v1`, then send
`{"type":"authenticate","ticket":"<one-use ticket>"}` before other commands.
The exact configured frontend Origin is required. No data or hello is sent before
authentication, and cookies alone do not authenticate a stream.

Tickets redeem once within 30 seconds. Browser authorization lasts at most 60
seconds and never beyond the verified provider token. Membership, key, grants,
revocation and expiry are checked while connected and before application frames.
A fresh authenticated exchange is needed for reconnect after authorization expiry;
canonical resume still has its own five-minute bound. Logout attempts revocation
before provider sign-out; unreachable authority cannot extend the original expiry.
Use the workspace [WebSocket lab](https://oddswire.io/app/websocket) where enabled.

The free session [capability control](/reference/getWebSocketCapabilities) describes
configured modes and access, not current source freshness. See also the restricted
[ticket exchange](/reference/createBrowserWSTicket) and
[revocation control](/reference/revokeBrowserWSTickets). New accounts remain zero-grant.

## Native snapshot delivery

Canonical namespaces retain transactional snapshot/delta/resume. Native
`sportsbooks` subscriptions require `view: "standard"`, one `source_id` and exact
native `fixture` string, plus existing native/source permissions. Retained Kambi
requires the exact `capture_id`; separately approved live Kambi follows the latest
attested complete capture using `mode: "live"` without `capture_id`.

Native `dataset_snapshot` frames have `delivery_mode: "snapshot_only"`,
`replace: true` and `dataset_data`, including an explicit empty array. Replace the
entire native view, preserving original native IDs, capture clocks, units and
missing reasons. There is no native tick journal or resume cursor. Retained active
labels remain historical research, not fresh executable prices. A source outage
resets the subscription instead of substituting saved prices.

The implemented complete-frame bound is 2,000 quote/coverage entries and 2 MiB.
Narrow canonical reads avoid unrelated namespace quote volume; active catch-up
uses bounded complete transactions. Oversized scopes or single transactions still
require narrower scopes or explicit resnapshot. Narrow a rejected subscription before connecting again.
